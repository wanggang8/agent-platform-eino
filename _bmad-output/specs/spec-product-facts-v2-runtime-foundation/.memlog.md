topic: Product Facts v2 与 Eino Runtime Foundation
updated: 2026-07-15T14:52
---

- (direction) 输入来自已批准 PRD、最终 UX、final Architecture Spine、Product Facts v2/Eino migration ADR、readiness gate 与现有 v1 schemas；采用直接提炼模式，不新增访谈假设。
- (note) Why：当前 v1 只持久化 StructuredResult 摘要，缺少可冻结查询集合、ActionDraft、逐条核验、稳定 SSE sequence 和真实 Eino ReAct/HITL，无法安全支撑 FOBrain 受控写闭环。
- (capability) CAP-1 Product Facts v2：系统能够用版本化、封闭的领域契约保存 Run、工具事实以及 QueryResultSnapshot、ActionDraft、ActionItem、ActionAttempt、FactEvent、VerificationEvidence；成功标准是 schema、Go domain、repository、SQLite 与投影映射一致且 v1 历史可读。
- (capability) CAP-2 安全结果与查询快照：系统能够持久化 Safety Gate 后的完整 StructuredResult，并冻结完整/部分覆盖、稳定排序和逐行安全事实；成功标准是刷新或重启后按 result_ref 恢复相同集合，全部动作只接受 complete_set。
- (capability) CAP-3 确定性多轮引用：系统能够让模型提取指代、由程序唯一解析 result_ref，并在上下文压缩后从事实库恢复；成功标准是唯一候选自动锁定、多候选进入 clarification、过期或越权引用被拒绝。
- (capability) CAP-4 不可变操作草案与确认：系统能够从冻结快照和人工参数生成 ActionDraft，并通过一次性 approval 进行二阶段确认；成功标准是 digest/actor/version/范围一致才可执行，任何变化创建新草案且未确认零写入。
- (capability) CAP-5 版本化能力策略与身份：系统能够从 Catalog v2 决定 freshness、verification、基数、分组、接收人来源、角色和对象权限；成功标准是 prepare/confirm 双检且任何未知身份、权限、版本或凭据上下文都 fail closed。
- (capability) CAP-6 逐条执行与客观核验：系统能够对 ActionItem 独立写入、回读和归类，并保留显式部分成功；成功标准是只有 provider 接受且 verifier 证据一致才成功，未知写入 reconcile，成功项永不重复执行。
- (capability) CAP-7 Eino-first 双入口执行：自然语言路径能够使用 Eino ChatModelAgent/Runner/ToolsConfig 和真实 interrupt/resume，确定性 Action API 能绕过模型但共用同一控制面命令；成功标准是两入口共享 draft、policy、approval、idempotency、execution 和 verification 事实。
- (capability) CAP-8 持久化 Run 与崩溃恢复：系统能够在客户端断线或进程重启后恢复安全步骤，并对不确定写入先核对；成功标准是 waiting continuation 可恢复、确认只消费一次、租约 fencing 生效、无法证明结果进入 manual_attention。
- (capability) CAP-9 同源产品投影与稳定 SSE：Workbench、ActionResult、replay、audit、Inspector 和模型上下文能够消费同一 Product Facts v2；成功标准是持久化 sequence、snapshot high-water、upsert/tombstone patch 和 view.replaced 重连无丢失/重复。
- (capability) CAP-10 可验证迁移与运行门禁：系统能够从 v1 前向迁移到 v2，并在受支持工具链、SQLite 连接策略、备份恢复和 readiness 检查通过后启用新 writer；成功标准是 G-ARCH-V2/G-TOOLCHAIN 具备证据且旧 v1 不被猜测回填。
- (constraint) 真实 FOBrain external mutation 在适用 G-FACT-01、G-WRITE-01..04、G-SAFE-01、G-ARCH-V2、G-TOOLCHAIN 全部 PASS 前禁止实现或启用。
- (constraint) Product Facts v1 保持历史只读；v1 ToolResult 因缺少完整事实不能创建 QueryResultSnapshot 或 ActionDraft，用户必须在 v2 Run 重新查询。
- (constraint) StructuredResult 必须先过 schema 和 Safety Gate，以不可变安全 JSON、schema_version、result_ref、SHA-256 内容摘要和大小持久化；raw provider payload 永不进入事实、模型上下文或产品出口。
- (constraint) 采用当前聚合状态加不可变 FactEvent，不采用依赖全量事件回放重建数据库的完整 Event Sourcing/CQRS。
- (constraint) Run.status 保持 created/running/waiting/succeeded/failed/cancelled/stopped；执行、验证、reconcile、manual_attention 只属于 ActionItem/Attempt，并按唯一状态映射投影。
- (constraint) QueryResultSnapshot 归属 workspace、conversation、actor；跨 conversation 或 actor 禁止复用，完整集合任一分页失败都不能声明 complete_set。
- (constraint) ActionDraft 一对一绑定 PendingInteraction 和一次性 approval ref；digest 使用 RFC 8785 JCS + SHA-256，确认后禁止重查替换对象或参数。
- (constraint) 所有写域默认二次确认；AI 不决定接收人、误报、延时或新期限，前端/HTTP/provider 不授予权限。
- (constraint) 派发和转发只能从 FOBrain 全员列表选人，同一接收人可合并、不同接收人拆 draft；延时每次单条且仅管理员；误报要求当前 actor 负责对象。
- (constraint) 聊天自然语言工具编排必须进入 Eino Runner；允许 Eino imports 仅在 execution、capabilities、observability、store/sqlite，facts/product/httpapi/providers/web 保持 Eino-free。
- (constraint) 聊天使用 staged Eino checkpoint，确定性 Action API 使用项目 continuation record；两者通过统一 ContinuationRef，禁止伪造或混称 Eino checkpoint。
- (constraint) 首版是模块化单体、单后端实例和 SQLite；WAL、每连接 foreign keys、busy timeout、migration、integrity、备份 restore 和 readiness 必须可验证。
- (constraint) 首版身份是受控单操作人，actor 来自 FOBrain current user 稳定业务 ID；共享凭据不声明多人审计。
- (constraint) API 使用 OpenAPI 3.1 和 JSON Schema 2020-12，前端只消费 generated contracts；成功业务 schema 直出，错误统一安全 envelope。
- (constraint) 首版只支持浅色桌面三栏和 1440x900 验收基线，最小工作宽度 1180px；不新增移动、暗色或触屏专用体验。
- (constraint) 下一实现阶段的 CI/发布工具链固定 Go 1.26.x 与 Node 24 LTS；npm 精确解析由 package-lock.json + npm ci 证明。
- (constraint) 所有 v2 状态迁移、幂等、checkpoint/continuation、SSE 和 verifier 行为必须先有 schema、fixture、contract tests 与故障恢复验收，不能只实现 happy path。
- (decision) SPEC 只定义 Product Facts v2 Runtime Foundation；FOBrain 四项具体写能力仍由 PRD/Product Issues 和后续 Epic/Story 承载，本 SPEC 不授权业务写入。
- (note) Non-goals：不实现真实 FOBrain 写动作、自动派发/自动决策/通知、移动端/暗色、多用户 SSO、PostgreSQL/微服务、完整事件溯源、跨 session 长期记忆或生产 MCP 市场。
- (note) Success signal：一次完整演示可在 v2 Run 查询并冻结事实、唯一解析引用、生成并确认不可变草案、逐条执行/回读或安全模拟、断线重连和进程恢复后由 Workbench/Action API/replay/audit 展示同一结果；所有未通过门禁的真实写入保持关闭。
- (requirement by preservation-review) 精确新增漏洞查询按 discovered_at 倒序并使用稳定业务身份作 tie-breaker；成功空集、无权与 provider 失败必须形成不同事实。
- (requirement by preservation-review) 统一漏洞行级事实至少包含 POC、IP、在线状态、业务系统、修复负责人；可用时包含业务系统负责人和运维负责人，缺失值不得由模型猜测。
- (constraint by preservation-review) FOBrain 人员候选必须来自当前可见全员列表并使用稳定业务身份；AI 不得推荐、选择或替换接收人。
- (constraint by preservation-review) 派发/转发仅可将操作人已经逐条判断为同一接收人的对象合并；不同接收人必须拆分草案。
- (requirement by preservation-review) manual_attention 在产品层显示为“待排查”，由 FOBrain 系统负责人排查；本产品不发送通知、消息或工单。
- (capability) CAP-11 操作记录安全投影：系统能够按 actor/workspace 从 Product Facts、ActionResult 与安全审计引用恢复跨会话只读操作记录；成功标准是固定入口默认发现最近六个月、未关闭对象持续可发现、详情同源且不产生重试或重新写入。
- (constraint) 2026-07-15：Item reconciling 唯一投影为待核验且 Run 保持 running；definitive failed 或 manual_attention 投影为待排查，deadline 与调用预算持久化且重启不重置。
- (constraint) 2026-07-15：操作记录只从 Product Facts/ActionResult 安全投影并在读取时重验 actor/workspace；禁止从聊天摘要、raw provider payload 或重新调用 FOBrain 重建，历史只读且不自动创建草案。
