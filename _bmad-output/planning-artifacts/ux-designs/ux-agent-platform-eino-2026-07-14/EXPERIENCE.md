# FOBrain 漏洞处置实验 Agent — Experience Spine

## Foundation

这是仅面向桌面浏览器、仅提供浅色主题的 Web Workbench。工作台采用 Vite、React、TypeScript、React Router、TanStack Query、Zustand、Radix UI Primitives、lucide-react 与项目 CSS；Radix 只提供无样式交互基础。`DESIGN.md` 是视觉身份与视觉组件规范，本文只规定信息架构、行为、状态、交互与可访问性；两份 spine 与任何示意图冲突时，以 spine 为准。

聊天是全部查询与动作的唯一入口。操作人用自然语言表达查询、派发、转发、误报或延时意图；AI 选择能力并组织安全事实，但不替操作人决定负责人、判断误报、决定是否延时或决定新期限。程序通过 Product Facts 中的安全结果引用冻结外部写入范围，不能依赖模型记忆、聊天摘要、自然语言关键词或 provider 原始数据。

### 可用性边界

| 范围 | 体验承诺 |
|---|---|
| 当前可启用 | 精确查询、安全摘要、百条级只读明细、右栏事实与执行记录查看。 |
| 门禁后的目标体验 | PI-002～PI-005 的动作准备、聊天内二次确认、受控写入与逐条回读。只有 `G-FACT-01`、适用的 `G-WRITE-*` 与 `G-SAFE-01` 通过后才可启用。 |
| 当前不可启用 | 真实派发、转发、误报、直接修复延时，以及可被误认为会触发这些写入的“确认”控件。当前收到写意图时，明确说明写域尚未启用，不生成可确认的动作草案。 |
| 始终禁止 | AI 推荐或推断负责人、自动确认、从只读明细发起写入、用接口成功或 FOBrain 通知替代回读成功、展示 raw JSON、provider 字段、内部 ID、token、密钥或英文内部状态码。 |

## Information Architecture

| ID | 表面 | 到达方式 | 目的 | 离开方式 |
|---|---|---|---|---|
| IA-01 | 聊天与操作记录主表面 | 打开产品、从 IA-02 返回，或点击左栏固定“操作记录” | 聊天模式发起全部查询与动作并承载结果；操作记录模式只读浏览获授权历史操作、筛选待核验／待排查结果。 | 从查询、审批、执行或历史记录的“查看全部”进入 IA-02；操作记录模式可返回当前聊天。 |
| IA-02 | 漏洞明细工作区 | IA-01 的“查看全部” | 只读查看百条级完整对象范围、统一行级事实与逐条结果；不准备、不确认、不取消、不执行动作。 | 返回来源卡所在的聊天位置，保留冻结范围与当前会话上下文。 |

工作台骨架在两张表面保持稳定：左侧是会话导航和独立于会话的系统固定入口“操作记录”，中间是当前表面的主要内容，右侧是事实与执行面板。IA-01 默认显示聊天时间线；点击“操作记录”后仍在 IA-01 中区切换为历史记录模式，不新增第三张表面。IA-02 中间显示高密度只读明细。右栏优先显示所选查询、操作记录或漏洞的安全事实与执行记录；OQ-08 关闭前不显示技术信息入口，关闭后也只能展示授权后的安全投影。

两张表面完成全部需求闭环：聊天负责“问、说、澄清、确认、取消、看结果”，IA-01 操作记录模式负责“重新找到历史批次”，IA-02 只读明细负责“核对全部对象”。右栏是两张表面的共享区域，不是第三张独立表面。会话切换不能覆盖历史查询快照；进入历史模式或 IA-02 也不能把记录／当前行选择误认为新的动作范围。

IA-01 当前首版参考[当前只读聊天](mockups/key-current-readonly-chat.html)，对应 READ-01 与 ST-11；IA-02 参考[分页漏洞明细](mockups/key-paginated-vulnerability-details.html)，对应 RD-01、RD-02、ST-23 与 ST-24；门禁后的审批、执行与混合结算参考[目标审批与部分失败](mockups/key-target-write-approval-partial-failure.html)。[精密指挥台方向稿](mockups/direction-precision-command.html)只用于视觉基线。所有 mock 都是视觉与状态参考，不是 DOM／接口合同；与两份 spine 冲突时，以 spine 为准。

## Voice and Tone

微文案冷静、精确、可核对。品牌声线与视觉人格由 `DESIGN.md` 定义；本文只约束产品如何表达事实、缺失、风险和下一步。

| 场景 | 使用 | 不使用 |
|---|---|---|
| 查询有结果 | “第 {N} 次查询：找到 {count} 条新增漏洞。查看全部。” | “我帮你找到了一些可能相关的漏洞。” |
| 新增查询为空 | “没有待派发漏洞。” | “看起来应该没有漏洞。” |
| 查询失败 | “无法读取漏洞事实。此次请求不是空结果。” | “没有查到结果。” |
| 当前负责人缺失 | “未分配” | 空白、“未知”或模型补全的人名 |
| 业务系统及业务／运维负责人缺失 | “未提供” | 空白、“未分配”或推测值 |
| 引用歧义 | “请确认你指的是哪次查询：第 2 次，19 条；第 5 次，11 条。” | 展示 `result_ref`、UUID 或自行选择一个结果 |
| 目标态待确认 | “待确认：派发给 {name}，共 {count} 条。前 5 条如下。” | “已为你派发。” |
| 目标态取消 | “已取消，未向 FOBrain 写入。” | “操作结束。” |
| 目标态部分失败 | “完成 {success_count} 条，待排查 {issue_count} 条，待核验 {pending_count} 条。” | “批量操作成功。” |
| 目标态结果待核验 | “已提交，当前无法确认最终结果。恢复连接后将从同一执行记录继续核验。” | “写入失败，请重试。” |
| 回读核验成功 | “派发完成”“转发完成”“已标记误报”“延时成功” | 仅凭接口成功显示“操作成功” |
| 最终失败／核验收敛后仍不一致 | “未完成，请联系 FOBrain 系统负责人排查。” | 自动重试、自动通知或隐去失败对象 |
| 写域未启用 | “当前仅支持查询与只读核对，此写操作尚未启用。” | 可点击的假确认、含糊的“暂不可用” |

状态与结论先说事实，再说影响；不使用庆祝语、拟人化承诺、置信度措辞或感叹号。技术原因只提供脱敏摘要，业务结果必须逐条保留。

## Component Patterns

行为规则如下；视觉规则由 `DESIGN.md.Components` 定义。名称是实现、验收与两份 spine 之间的统一契约。

| 组件 | 使用位置 | 行为规则 |
|---|---|---|
| 工作台骨架 | IA-01、IA-02 | 固定左／中／右三区职责；只允许中区在聊天时间线与漏洞明细工作区之间切换。切换表面保留会话、来源卡位置、冻结范围与右栏上下文。实现使用可命名的 `nav`、唯一 `main` 和补充 `aside` landmark，并提供“跳到主内容”。仅桌面浅色，不产生移动布局、抽屉导航或主题切换。 |
| 会话导航 | 左栏 | 顶部或固定分组提供系统入口“操作记录”，其视觉和语义与聊天会话区分；其余区域展示并切换会话，当前目标有明确选中态。切换不得合并、覆盖或重建查询结果引用；待确认状态必须可识别。会话标题和摘要不展示内部 ID 或敏感事实。 |
| 操作记录列表 | IA-01 中区，操作记录模式 | 只从 Product Facts／ActionResult 安全投影读取当前 actor/workspace 的记录，按操作时间倒序；默认展示最近六个月，同时让未关闭的待确认、执行中、待核验和待排查记录持续可发现。支持时间、动作类型、状态筛选与“待核验／待排查”快捷筛选；加载、空、失败、无权限和损坏引用分别提示。打开记录进入 IA-02 只读逐条结果，不重新调用 FOBrain、不自动创建草案或重试。 |
| 聊天时间线 | IA-01 中区 | 按时间顺序承载消息气泡与所有业务卡。查询、动作、澄清、确认、取消、执行和结果都在此发生；进入 IA-02 后返回时定位到来源卡。百条明细不在时间线展开。 |
| 消息气泡 | 聊天时间线 | 区分操作人输入与 Agent 回复；Agent 只使用安全 Product Facts 摘要。需要指定负责人时，只提供 FOBrain 全部人员的中性选择，不排序推荐、不推断、不补全；目标人员不能唯一确定时转为澄清卡。 |
| 查询结果卡 | 聊天时间线 | 显示用户可理解的查询序号、摘要、数量与观察时间；只显示新增数量和安全摘要，不展开百条明细。“查看全部”进入 IA-02；0 条与失败使用不同状态。该卡对应不可变查询结果快照，不显示技术引用。 |
| 漏洞明细工作区 | IA-02 中区 | 高密度、只读展示查询、审批或执行结果的完整对象集合。按冻结快照每页 100 条分页，显示当前页、总页数、总数及加载状态；支持首页、上一页、下一页、末页和页码跳转。保留左侧会话导航；行选择只更新右栏，不改变动作范围。只允许分页、查看事实和只读页加载恢复，不提供确认、取消、业务写按钮、批量编辑或内联编辑。 |
| 漏洞事实行 | 漏洞明细工作区 | 至少显示快照内行序号、POC、IP、IP 在线／离线状态、业务系统、当前修复负责人和逐条状态；派发核对还显示业务系统负责人、运维负责人、发现时间。POC 在表格中单行截断；多个 IP 显示首个 IP 和“其余 N 个”；选择行后右栏完整展示 POC 与全部 IP。发现时间统一为 `YYYY-MM-DD HH:mm:ss（UTC+8）`。当前负责人缺失显示“未分配”，业务系统及两类负责人缺失显示“未提供”。行按交互式 grid 的 roving focus 规则只保留一个 Tab 停靠点，选择或 Enter 只更新右栏，始终只读。 |
| 审批卡 | IA-01，目标体验 | 只绑定已冻结的动作草案；显示所引用查询、动作、目标变化、目标负责人或状态／期限、总数及前 5 条漏洞。“查看全部”进入 IA-02；“确认”和“取消”仅存在于该卡且只由实际执行人触发。草案内容变化必须形成新草案并重新确认。当前写域未过门禁时不得提供可操作的审批卡。 |
| 澄清卡 | IA-01 | 在引用缺失、候选不唯一、目标人员不能唯一确定或必要参数缺失时出现；只列安全摘要、数量与时间，让操作人明确选择或补充。澄清完成前不生成动作草案，不发生写入。 |
| 人员选择卡 | IA-01，目标体验 | PI-002／PI-004 写域门禁通过后，从 FOBrain 人员安全投影中人工单选接收人。提供搜索、候选加载、空结果、失败、同名消歧、不可选状态和最终选中复核；不使用 AI 推荐、自由文本姓名或内部 ID。搜索、排序、消歧字段和人员状态规则在 OQ-02 关闭前不得实现为可写入口。 |
| 执行结果卡 | IA-01，目标体验 | 先显示批次摘要，再保留每条完成、待排查或待核验事实；“查看全部”进入 IA-02 查看完整逐条结果。完成只由回读事实决定，部分失败不能被完成汇总覆盖。卡片不提供通知、自动处理或未经定义的再次执行入口。 |
| 事实与执行面板 | IA-01、IA-02 右栏 | 默认提供“事实”和“执行记录”：随当前查询、来源卡或所选漏洞更新，但不改变动作范围。写操作的安全执行记录至少显示业务动作、实际确认人安全显示名／角色、确认或取消时间、来源查询序号与观察时间、冻结对象数量、目标变化摘要、执行／回读阶段、完成／待排查／待核验计数及安全错误摘要；不显示内部引用。技术信息的授权与字段 allowlist 在 OQ-08 关闭前整体隐藏，不根据前端角色名猜测。 |
| 消息输入框 | IA-01 | 是查询与动作意图的唯一输入；提交后消息进入聊天时间线。执行中不把重复输入解释为再次确认；确认／取消必须在审批卡完成。输入不解析为前端硬编码业务分支，范围锁定由后端安全引用完成。 |
| 状态标记 | 全局 | 以文字、图标与颜色共同表达状态，不能只依赖颜色。列表、审批、结果与右栏对同一事实使用同一标签；用户可见文案不用英文内部状态码。 |

## State Patterns

当前只读状态与门禁后的目标写状态使用同一事实链。所有外部失败都显示脱敏原因；任何失败、缺失或中间态都不能由模型总结为成功。

| ID | 状态 | 适用表面 | 处理规则 |
|---|---|---|---|
| ST-01 | 待命 | IA-01 | 聊天时间线可读，消息输入框可提交查询；不预设任务、不自动发起查询或动作。 |
| ST-02 | 首屏加载／会话恢复 | IA-01 | 工作台骨架先稳定出现，三个区域分别标明正在恢复；恢复完成前不把历史摘要当作可执行范围。 |
| ST-03 | 查询中 | IA-01 | 在对应消息后显示明确进行中状态；保留用户原始表达，不制造预计完成时间、虚构数量或中间事实。 |
| ST-04 | 查询成功且有结果 | IA-01 | 生成查询结果卡，显示序号、摘要、数量和时间；右栏更新为同一安全事实来源。 |
| ST-05 | 空结果 | IA-01 | 仅当新增漏洞接口成功且返回 0 条时显示“没有待派发漏洞”；不生成虚假明细，不与失败合并。 |
| ST-06 | 字段缺失 | IA-01、IA-02 | 当前修复负责人显示“未分配”；业务系统、业务系统负责人、运维负责人显示“未提供”。这些缺失不由 AI 补全。 |
| ST-07 | 澄清中 | IA-01 | 显示澄清卡；候选明确前不生成动作草案。完成澄清后绑定被明确选择的安全引用，而不是重读聊天文字。 |
| ST-08 | 无权限 | IA-01、IA-02 | 与空结果、数据不足、外部失败分开显示；不泄露不可见对象。非管理员表达直接延时意图时不准备写入。 |
| ST-09 | 数据不足 | IA-01 | 人员列表读取失败、目标人员不能唯一确定或必要写参数缺失时阻断动作准备。业务系统或业务／运维负责人缺失本身不阻断派发，只按 ST-06 展示。 |
| ST-10 | 查询／外部失败 | IA-01、IA-02 | 显示脱敏失败摘要并明确“不是空结果”；不生成结果快照、不保留未经验证的 provider 数据。 |
| ST-11 | 写域当前不可用 | IA-01 | 对 PI-002～PI-005 写意图说明当前仅支持查询与只读核对；不生成可确认审批卡，外部写入数为零。 |
| ST-12 | 待确认 | IA-01，目标体验 | 审批卡展示冻结范围、目标变化、总数与前 5 条；全部对象可经“查看全部”核对。等待实际执行人确认或取消，等待期间无外部写入。 |
| ST-13 | 已取消 | IA-01，目标体验 | 仅在操作人主动取消后显示“已取消，未向 FOBrain 写入”；草案不进入执行，外部写入数为零。尚未确认不伪装成主动取消。 |
| ST-14 | 执行中 | IA-01，目标体验 | 审批卡转为不可再次确认的执行状态；保持冻结对象与目标可见，不接受重复确认扩大范围。 |
| ST-15 | 回读中 | IA-01，目标体验 | 写请求结束后仍不显示成功；逐条等待负责人、处置状态或状态与期限的安全回读事实。 |
| ST-16 | 状态不允许 | IA-01，目标体验 | 直接延时遇到不允许的当前状态时阻断写入，显示可识别的状态不符合原因；不推断允许状态集合。 |
| ST-17 | 写入失败 | IA-01、IA-02，目标体验 | 对象保持未完成并标记“待排查”，显示脱敏原因；不把其他对象的成功覆盖到该条。 |
| ST-18 | 混合结算 | IA-01、IA-02，目标体验 | 执行结果卡同时显示完成数、待排查数与仍待核验数；IA-02 逐条区分三类对象，任何一类都不能被批次总数覆盖。 |
| ST-19 | 回读不一致 | IA-01、IA-02，目标体验 | 即使写接口返回成功，回读目标未达成也不能显示完成。仍在 verification policy 的核验期限／调用预算内时进入 ST-27“待核验”；明确失败，或期限／预算结束仍不一致时才显示“未完成／待排查”，并保留期望变化与实际安全事实。 |
| ST-20 | 成功 | IA-01、IA-02，目标体验 | 派发／转发以负责人匹配为准，误报以处置状态为“误报”为准，延时以状态为“延时”且期限匹配为准；延时文案为“延时成功”。 |
| ST-21 | 引用失效／事实变化 | IA-01，目标体验 | 引用不存在、失效、权限变化或关键事实变化时使草案失效；明确要求重新查询并重新确认，不沿用旧批准。 |
| ST-22 | 离线／连接不可用 | IA-01、IA-02 | 不把缓存、聊天摘要或模型记忆当作新外部事实，也不进入写入；仅说明当前无法连接。重新连通后的恢复遵循 RD-04，并只从持久化 Product Facts 与安全快照继续。 |
| ST-23 | 焦点／选中 | IA-01、IA-02 | 键盘焦点始终可见；IA-02 的当前行选择只驱动事实与执行面板，不构成选择写入对象，也不改变冻结范围。 |
| ST-24 | 明细加载／局部失败 | IA-02 | 首次进入显示来源查询、固定总数与页数占位，不把旧列表当成新事实。目标页读取失败时保留最后已核验页面与页码，明确失败页和“不是空结果”；“重新加载本页”只读取同一冻结快照，不触发新查询或写入。 |
| ST-25 | 审批已过期 | IA-01，目标体验 | 禁用确认，明确“审批已过期，未因本次确认产生写入”；要求重新查询、重新准备并重新确认，不把过期归为用户取消。 |
| ST-26 | 提交锁定／重复提交 | IA-01，目标体验 | 第一次确认后立即锁定确认与取消控件并进入执行中；重复提交只投影同一权威终态，不再次 mutation。聊天中的重复文字不构成确认。 |
| ST-27 | 执行结果待核验 | IA-01、IA-02，目标体验 | 确认请求可能已到达外部系统、当前无法核对最终结果且仍在核验期限／预算内时，保留冻结范围并禁用再次确认；恢复后从同一 Product Facts／执行记录继续对账，不提供“再次执行”入口。期限／预算结束仍无法证明目标时转入 ST-19 待排查。 |
| ST-28 | 权威恢复分流 | IA-01，目标体验 | 重启、重新进入会话或打开操作记录后，只从 Product Facts 恢复：有效 waiting 草案经权限、摘要与有效期复核后恢复待确认；过期进入 ST-25；已提交进入 ST-14／ST-15／ST-27；终态进入 ST-18／ST-19／ST-20。不得从聊天摘要重建范围，重启不得重置核验期限或预算。 |
| ST-29 | 历史结果只读 | IA-01、IA-02 | 用户从左栏固定“操作记录”进入 IA-01 历史模式，默认查看最近六个月，未关闭对象在关闭前持续可发现；每次读取重新校验当前 actor/workspace。打开记录后可进入 IA-02 查看原逐条结果。历史只读，不从聊天摘要或重新调用 FOBrain 重建，不自动恢复成待确认草案，也不新增重试能力；六个月不是物理删除策略。 |

## Interaction Primitives

- 鼠标点击和标准键盘操作并重；所有可交互元素可由 `Tab` 到达，以 `Enter` 或 `Space` 触发。
- DOM 顺序就是焦点顺序，禁止使用正 `tabindex` 重排。工作台顺序为会话导航 → 中区标题、时间线与输入框 → 右栏；skip link 可直接进入当前 `main`。
- `Esc` 只退出当前临时展开内容或返回上一级阅读上下文；不能代表审批卡中的“取消”，避免无意改变待确认状态。
- “查看全部”是从查询结果卡、审批卡或执行结果卡进入漏洞明细工作区的统一动作；返回后焦点回到来源卡。
- 漏洞明细工作区使用快照分页，每页 100 条；新到漏洞不改变已打开快照的总数、页数和顺序。切换页后记录页码、当前行序号和页面滚动位置，进入右栏或返回来源卡后恢复原位置。
- 漏洞事实表采用单一 Tab 停靠点的交互式 grid：上下方向键移动当前行，Home／End 到当前页首尾，PageUp／PageDown 切换相邻页，Enter 更新右栏；读屏获得全局 `aria-rowcount`、跨页 `aria-rowindex`、当前页和总页数。行点击或键盘选择不出现复选框式写入范围选择，不产生动作草案。
- 表格摘要与右栏完整值必须来自同一安全行级事实：视觉截断不改变单元格的完整可访问名称；右栏 POC 完整换行，多个 IP 按一项一行展示。发现时间统一显示为 `YYYY-MM-DD HH:mm:ss（UTC+8）`，不按浏览器本地时区漂移。
- 审批卡中的“确认”与“取消”是唯一写决策原语；确认前零写入，取消或未确认同样零写入。
- 同一负责人才能形成一个合并派发或转发草案；不同负责人必须拆成不同审批卡，不能在一个确认中混合。
- 查询结果中的每条事实拥有仅在该次查询快照内有效的用户可见行序号。操作人可在聊天中通过“第 N 次查询 + 行序号／可见 POC 与 IP”指明子集；程序只接受解析后仍属于相应安全结果引用的行级事实，歧义、重叠归属或遗漏目标时进入澄清，不让模型静默选取。
- 多个查询结果可形成一个草案时，审批卡逐个显示用户可理解的查询序号、摘要和观察时间，并显示确定性去重后的最终冻结总数；“查看全部”打开最终冻结集合而不是任一来源查询。不同负责人仍拆成不同草案。
- 多轮指代由 AI 映射到安全结果引用，程序校验归属、实体类型、权限、有效性与完整性；歧义进入澄清卡。
- 禁止拖拽决定负责人、悬停才可见的关键动作、从右栏或只读明细直接写入、自动确认、通知中心、消息／邮件／webhook／催办、AI 推荐或自动补全负责人。

## Accessibility Floor

- 桌面 Web 表面满足 WCAG 2.2 AA；视觉对比、焦点样式与状态色由 `DESIGN.md` 保证。
- 阅读和焦点顺序遵循 DOM：会话导航 → 中区标题、时间线与消息输入框 → 事实与执行面板。用户主动提交后生成查询、澄清或审批卡时，焦点保持在输入框，并在输入框旁提供“转到最新结果／待确认操作”；后台更新不抢焦点。表面切换后焦点进入 `main` 标题并播报表面名称和结果数量。
- 查询进度、待确认和执行进度使用单一 `role=status`／polite 摘要；批量回读只播报节流后的批次计数和最终“完成 X、待排查 Y、待核验 Z”，逐条事实由 IA-02 阅读。阻断或最终失败使用一次明确错误摘要；同一事件若已移动焦点到错误摘要，不再重复 live 播报。
- 状态标记同时提供可读文字和非颜色线索；在线／离线、成功／失败／待排查、已选中／未选中均不能只靠颜色区分。
- 漏洞明细工作区提供结构化表头、行列关联和可感知的当前行；长内容可完整读取，截断文本不能成为唯一信息载体。
- 审批卡的动作、目标变化、数量、前 5 条与“查看全部”关系必须可由读屏理解；“确认”与“取消”使用完整可辨名称。
- 进入 IA-02 后焦点落在工作区标题；返回 IA-01 后焦点回到来源卡。错误发生后焦点进入对应错误摘要，不跳到技术信息。
- 动态内容不自动抢夺键盘焦点；动画不是理解状态或完成任务的必要条件。
- 文字缩放至 200% 时，聊天、澄清、审批和结果卡在中栏内重排且不遮挡操作；只有 IA-02 明细表自身允许水平滚动，错误、确认和结果摘要不得依赖整页横向滚动。

## Key Flows

READ-01 是当前可启用的完整只读旅程；UJ-01～UJ-05 是门禁后的目标体验。当前产品在目标旅程中只执行查询与只读核对步骤，到达写意图时进入 ST-11，不能继续到审批与执行。

### READ-01 — 当前可启用的新增漏洞只读核对（林岚，产品中心运营，工作日上午开始每日检查）

1. 林岚在消息输入框中要求查询全部新增漏洞。
2. Agent 调用精确新增查询；聊天时间线显示查询中，成功后生成带查询序号、总数、观察时间与安全摘要的查询结果卡。
3. 林岚点击“查看全部”进入漏洞明细工作区，按发现时间倒序核对统一行级事实；新到漏洞不改变已打开查询快照的顺序与总数。
4. 她选择任一行查看右栏安全事实与查询记录，行选择不形成写范围；返回后焦点回到来源卡。
5. 她在聊天中要求派发这些漏洞；由于写域门禁尚未通过，系统进入 ST-11，不生成审批卡、不显示确认按钮，也不调用外部写接口。
6. **Climax：** 林岚看到“当前仅支持查询与只读核对，此写操作尚未启用”，并能客观确认该轮外部写入为零；本轮查询结果仍可只读重开。

失败路径：新增查询成功且为 0 条时显示“没有待派发漏洞”；查询失败明确“不是空结果”。明细后续范围加载失败时保留已核验快照并标出未加载范围，不把聊天摘要或旧缓存冒充新事实。

### UJ-01／PI-002 — 运营手动派发新增漏洞（林岚，产品中心运营，工作日上午开始每日检查）

1. 林岚在消息输入框中要求查询全部新增漏洞。
2. Agent 调用精确新增查询；聊天时间线显示查询中，随后显示查询结果卡，包含查询序号、安全摘要、新增总数与时间。
3. 林岚点击“查看全部”进入漏洞明细工作区，按发现时间倒序核对 POC、IP、在线状态、业务系统、当前修复负责人、业务系统负责人和运维负责人；缺失值按确定性文案展示。
4. 她返回来源卡，在聊天中从 FOBrain 全部人员的中性选择中手动指定目标负责人；AI 不给推荐。
5. 她表达“把这些漏洞派发给该负责人”。AI 将指代映射到安全查询结果引用，程序校验并冻结对象集合。
6. 审批卡显示“派发”、目标负责人、来源查询、总数与前 5 条；林岚可再次“查看全部”，确认与取消仍留在聊天中。
7. 林岚点击“确认”；系统才逐条写入，并逐条回读当前修复负责人。
8. **Climax：** 执行结果卡以回读事实显示每条“完成”“待核验”或“待排查”，林岚能从汇总进入完整结果，确认没有对象被数量汇总掩盖。

失败路径：查询成功且为 0 条时显示“没有待派发漏洞”；查询失败时明确不是空结果。若引用失效、权限变化或事实变化，原草案失效并要求重新查询、重新确认。若部分写入或回读不一致，成功项完成；deadline／预算内未知或不一致按 ST-27 显示待核验，可证明未应用或收敛后仍未知／不一致按 ST-19 显示待排查。

### UJ-04／PI-003 — 运营标记误报（周妍，产品中心运营，已人工判定一条本人负责的漏洞为误报）

1. 周妍在聊天中查询或指明自己可见的一条漏洞，并通过查询结果卡与只读明细核对统一事实。
2. 她在聊天中明确表达将该条漏洞标记为误报；AI 不把判断扩展成规则，也不扩展到其他漏洞。
3. 程序校验单条安全结果引用并冻结动作草案。
4. 审批卡逐条显示漏洞事实与“处置状态将变更为误报”；确认前没有外部写入。
5. 周妍点击“确认”；系统执行后回读处置状态。
6. **Climax：** 只有回读状态为“误报”时，执行结果卡与漏洞事实行同时显示完成，右栏事实与执行记录一致。

失败路径：周妍无权限、引用不唯一或引用失效时不生成动作草案，分别进入无权限或澄清状态；她点击“取消”时显示零写入。回读状态不是“误报”但仍在 deadline／预算内时按 ST-27 待核验；可证明未应用或收敛后仍不一致时按 ST-19 待排查。

### UJ-02／PI-004 — 运营主动转发责任人（陈沐，运营，发现一组可见漏洞需要主动转给同一负责人）

1. 陈沐在聊天中查询需要转发的可见漏洞；该流程不依赖错派检测、首次派发失败或其他前置动作。
2. 查询结果卡提供摘要和数量；他通过“查看全部”在漏洞明细工作区只读核对完整对象。
3. 他返回聊天，从 FOBrain 全部人员的中性选择中手动指定接收人，并表达转发意图；AI 不推荐接收人。
4. 程序验证查询结果引用，只把最终接收人相同的漏洞冻结到同一个动作草案；不同接收人的对象形成不同审批卡。
5. 审批卡显示来源查询、动作、目标接收人、总数与前 5 条；陈沐在聊天中确认或取消。
6. 确认后系统逐条执行并回读当前修复负责人。
7. **Climax：** 执行结果卡只把负责人已变为指定人员的漏洞标为完成；陈沐在同一结果中看清待核验和待排查对象。

失败路径：目标人员不能唯一确定或人员列表读取失败时进入澄清／数据不足，不准备写入。若一条或多条回读负责人不匹配，匹配项完成；deadline／预算内不匹配按 ST-27 待核验，可证明未应用或收敛后仍不匹配按 ST-19 待排查，不能把批次显示为全部成功。

### UJ-03／PI-005 — 管理员直接修复延时（高敏，管理员，已在产品外与相关人员确定一条漏洞的新期限）

1. 高敏在消息输入框中指明单条漏洞、新修复期限和可选原因；产品不参与线下沟通，也不决定是否应该延时。
2. Agent 查询该条漏洞，查询结果卡与右栏展示统一事实和当前状态。
3. 程序确认管理员权限、单条范围和必要参数；若当前状态不允许直接延时，则在写入前阻断。
4. 审批卡显示该条漏洞、将设置的新期限与已填写的可选原因；确认与取消只在聊天中提供。
5. 高敏点击“确认”；系统执行后同时回读漏洞状态和修复期限。
6. **Climax：** 仅当状态为“延时”且期限等于指定值时，执行结果卡显示“延时成功”；右栏保留相同安全事实与执行记录，不展示成功字段明细或原始响应。

失败路径：非管理员、非单条范围或状态不允许时零写入；高敏取消时零写入。回读状态／期限任一不匹配但仍在 deadline／预算内时按 ST-27 待核验；可证明未应用或收敛后仍不匹配时按 ST-19 待排查并显示脱敏原因。

### UJ-05 — 处置异常（林岚，运营，正在核对一批已确认执行的漏洞结果）

1. 林岚在执行结果卡看到完成、待排查和待核验三类计数。
2. 她点击“查看全部”进入 IA-02，逐条核对 POC、IP、当前负责人或处置状态以及安全错误摘要。
3. 对明确失败，或核验期限／预算结束仍不一致的对象，系统保持“待排查”，不自动重试、不发送通知，也不把批次包装成成功。
4. 对确认后连接中断且结果未知、但仍在核验期限／预算内的对象，系统保持 ST-27；恢复后沿同一执行记录继续回读，不能生成第二次写入。
5. 林岚离开原会话或重新登录后，从左栏固定“操作记录”按状态筛出同一批次；系统重新校验权限，并从原 Product Facts 展示记录。
6. **Climax：** 林岚能准确区分已完成、待排查与待核验对象，并看到“未完成，请联系 FOBrain 系统负责人排查”的确定下一步。

失败路径：默认六个月外的终态记录不出现在初始列表；未关闭记录仍持续可发现。当前权限变化或引用损坏时，系统进入无权限或不可用状态，不泄露对象，也不从聊天摘要或重新调用 FOBrain 重建结果。

## Inspiration & Anti-patterns

选定方向是“精密指挥台”：保留高密度三栏、硬边界、聊天主入口和明确状态语义。拒绝“纸本审阅台”的暖色编辑感，因为它削弱安全运营的确定性；拒绝“信号矩阵”的暗色监控感，因为首版只做浅色，产品核心是事实核对与受控动作，不是实时大屏监控。正式视觉参考必须按两份 spine 修正，不能把未选方向或工作稿中的临时颜色带入实现。
