# PI-003：漏洞误报标记

## Background

日常漏洞运营中，个别漏洞需要标记为误报。人工操作人确认漏洞属于自己负责，并自行判断其为误报；这一判断不由 AI 或自动规则作出。

误报标记会改变漏洞处置结论，和首次派发、责任人转发、修复延时是不同业务动作。它属于数据修改，必须经过执行人二次确认。当前项目没有 live 验证的漏洞写域 capability。

该动作没有固定发生频率，遇到需处置的误报即操作一次；单次约几分钟。

未及时标记不会造成直接业务后果，只会使该漏洞持续显示为未处理。

## Goal

让人工操作人对自己确认的误报漏洞，在二次确认后标记为误报，并能客观核验该处置结果。

不包含自动误报判定、自动修改、责任人派发／转发、修复延时或修复完成。

## 业务输入与输出

| 类型 | 内容 |
| --- | --- |
| 输入 | 操作人确认属于自己负责的漏洞；人工误报判断。统一漏洞卡片展示 POC、IP、IP 在线／离线状态、业务系统和修复负责人；二次确认页在此基础上展示将变更为“误报”的状态。 |
| 输出 | 逐条展示统一漏洞卡片内容、误报标记结果及成功／失败状态；本产品不发送通知。 |
| 成功证据 | 回读确认漏洞处置状态变为“误报”即可。源码可支持该状态变更，但目标部署接口尚未验证。 |

## 验收标准

### AC-01：人工判断后可发起误报标记

Given：人工操作人确认一条漏洞属于自己负责，并判断该漏洞为误报。  
When：操作人发起误报标记。  
Then：系统只准备该条漏洞的误报标记，不将该判断扩展为自动规则或其他漏洞的自动修改。

### AC-02：未二次确认不得写入

Given：操作人已准备误报标记，且确认页展示统一漏洞卡片内容（POC、IP、IP 在线／离线状态、业务系统、修复负责人）和将变更为“误报”的状态。  
When：操作人未完成二次确认或取消确认。  
Then：系统不得向外部系统写入误报标记。

### AC-02a：误报使用统一漏洞卡片

Given：操作人查看一条待标记误报的漏洞。  
When：系统展示该漏洞的列表、确认或结果。  
Then：系统展示统一漏洞卡片内容（POC、IP、IP 在线／离线状态、业务系统、修复负责人）；误报操作只额外展示本次状态变化与结果。

### AC-03：成功必须可回读

Given：操作人已完成二次确认。  
When：系统执行误报标记。  
Then：只有回读确认该漏洞处置状态为“误报”时，才显示标记成功。

### AC-04：失败进入缺陷排查

Given：误报标记写入失败，或回读后漏洞状态仍不是“误报”。  
When：操作人核验该漏洞未完成误报标记。  
Then：该漏洞不得显示为已标记误报；操作人联系 FOBrain 系统负责人排查 bug。

### AC-05：产品不发送通知

Given：一条漏洞已标记误报成功。  
When：系统完成结果反馈。  
Then：本产品不向任何人发送通知；FOBrain 自身通知不作为本产品能力或成功条件。

## 未决项与准入限制

- 成功提示尚未确认。
- “自己负责”的目标部署权限定义和误报状态值域／写入／回读接口尚未 live 验证。
- 当前项目没有漏洞写域 capability；在目标部署写入、回读与补救证据补齐前不得实施。
