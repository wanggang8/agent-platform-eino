# PI-001：公司全量业务主机在用情况梳理

> 这是基于一条近期真实任务形成的 Product Issue 草案。它不是 final PRD 需求，也不代表当前实现已覆盖；异常处理、目标部署数据时效和任务效果仍待验证。

> 价值结论：该任务通常半年一次、最近一次约 30 分钟，且没有返工、错报、老板追问或实际业务后果。它不得单独驱动首版产品范围；只可作为共享能力的验收样本，或在出现新的高价值证据后重新评估。

## Background

老板通常每半年需要梳理一次公司全部业务系统实际使用的主机情况。最近一次从开始梳理到老板确认约 30 分钟。当前运营只能先查看业务系统，再对每个业务系统分别查询全部 IP 资产，并按资产状态手工统计在线和离线数量，最后整理结果表等待老板确认。

现有产品虽然已有若干 FOBrain 查询集成，但尚不能按业务系统读取关联 IP 资产，也不能在产品事实中保留业务、IP、状态和重要程度的行级结果。因此无法直接交付该任务所需的全量结果表。

## Goal

让产品中心／运营能够完成公司全量业务系统的主机在用情况梳理，并向老板提供可确认的结果表：每个业务系统的主机总数、在线数、离线数、具体离线 IP 和业务系统重要程度。

“真实在用”在本任务中定义为资产状态在线。

## 业务输入与输出

| 类型 | 内容 |
| --- | --- |
| 输入 | FOBrain 中全部业务系统；各业务系统关联的全部 IP 资产；每个 IP 资产的在线／离线状态；业务系统重要程度。 |
| 输出 | 按业务系统汇总的结果表，字段为业务系统、主机总数、在线数、离线数、具体离线 IP、业务系统重要程度。 |
| 完成证据 | 老板确认结果表。 |

## 验收标准

### AC-01：全量业务范围

Given：FOBrain 中存在业务系统列表，且本次任务没有业务系统排除范围。  
When：运营发起公司业务主机在用情况梳理。  
Then：系统对该次业务系统列表中的每一个业务系统完成关联 IP 资产判断并保留一行；没有关联 IP 资产的业务系统不需要进行主机在用分析，主机总数、在线数和离线数均显示 `0`。

### AC-02：每业务系统的主机状态汇总

Given：某业务系统关联的全部 IP 资产及其在线／离线状态可被读取。  
When：系统生成该业务系统的结果行。  
Then：该行包含业务系统、主机总数、在线数、离线数、具体离线 IP、业务系统重要程度；当业务系统没有重要程度时，该单元格留空；其中“真实在用机器数”等于在线数。

### AC-03：计数与离线明细一致

Given：某业务系统的 IP 资产状态读取成功。  
When：系统完成该业务系统的统计。  
Then：主机总数等于在线数加离线数，具体离线 IP 的数量等于离线数。

### AC-04：业务确认结束

Given：公司全量业务系统的结果表已生成。  
When：老板确认该结果表。  
Then：该次梳理被标记为已完成。

### AC-05：跨业务关联 IP 的计数

Given：同一个 IP 资产关联多个业务系统。  
When：系统生成各业务系统的结果行。  
Then：该 IP 分别计入每个关联业务系统的主机总数，并按其资产状态分别计入这些业务系统的在线数或离线数；不得跨业务去重。

## 未决项与准入限制

- 无关联 IP 资产的业务系统不需要进行主机在用分析，但结果表保留一行，主机总数、在线数和离线数均为 `0`。
- IP 状态在实际业务中视为必有；目标部署返回缺失／未知状态时的保护规则尚未获得证据。
- 没有业务重要程度时，该结果表单元格留空。
- 查询分页失败时的实际处理规则尚未获得证据。
- 本 Issue 不定义公司维度的去重主机总数；若未来需要展示，必须新增独立的业务口径和验收标准。
- 任务频率已知为通常半年一次，但最近一次的实际耗时、返工和错误成本尚未获得证据，不能据此宣称节省时长或确定首版优先级。
- 最近一次实际耗时已知为约 30 分钟。按半年一次计算，直接人工投入约每年 1 小时；除非存在其他可验证后果或可复用价值，本 Issue 不足以单独支持独立产品投资。
- 最近一次没有发生返工、错报、老板追问或其他实际后果；因此当前状态为 `LOW_VALUE_CANDIDATE_NOT_MVP_DRIVER`，不得进入 final PRD 的首版范围。
- 目标部署的资产状态数值映射、状态更新时间、离线阈值和全量分页覆盖尚未确认。
- 当前产品缺少按业务系统读取关联 IP 资产的能力，且 Product Facts 不保留 IP／状态／重要程度的行级输出；这些是实现前必须满足的产品契约，不是本文件指定的技术方案。
- 在异常处理规则与目标部署证据补齐前，本 Issue 不得升级为 final PRD requirement 或 `TASK_EFFECTIVE`。
