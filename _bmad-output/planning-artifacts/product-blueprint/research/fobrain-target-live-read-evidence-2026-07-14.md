# FOBrain 目标部署新增漏洞与人员读取证据

## 结论

目标部署的只读 API 已证明能够支撑精确新增漏洞队列和全量人员选择，但当前 Eino 产品尚未接入这两项能力，也没有统一行级 Product Facts。因此：

- `G-READ-01` 的目标部署 API 证据通过；
- `G-READ-02` 的目标部署 API 证据通过；
- `G-FACT-01` 只有源数据可得性证据，产品契约与投影仍未通过；
- 未执行任何派发、转发、延期或误报写操作，所有 `G-WRITE-*` 继续阻塞。

## 验证范围与方法

- 使用当前用户凭据对目标部署执行只读请求；凭据只在进程运行时注入，没有写入仓库、报告或日志。
- 精确筛选漏洞状态 `0`，按发现时间倒序分页读取全部结果。
- 分页读取全部人员列表。
- 对漏洞行级字段做脱敏覆盖统计，并抽样通过资产查询核对 IP 在线状态和关联信息。
- 使用随机、不可能命中的关键词执行同一新增漏洞查询，验证“成功且 0 条”可以与请求失败区分。
- 报告只保留数量、布尔断言、字段缺失统计和类型形状；不保存真实漏洞、IP、人员、业务系统或 provider raw payload。

## 当前产品实现缺口

1. `liveThreatStatusCodes` 的 `open` 会混合多个未处理状态，数字解析又排除 `0`，所以当前 Eino capability 不能表达“仅新增”。
2. 当前 capability catalog 没有 FOBrain 全量人员列表能力。
3. `StructuredResultCandidate.ItemCount` 明确不进入 Product Facts，`StructuredResultRef` 仅保留引用和摘要；当前 Workbench／Action API 无法消费漏洞行级事实。
4. 统一卡片需要独立安全 schema、fixture、Product Facts 存储和产品投影；源字段缺失时必须显式为空／未分配，不能由 AI 补全。
