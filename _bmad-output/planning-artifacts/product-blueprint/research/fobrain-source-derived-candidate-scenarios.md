# 从 FOBrain 源码提炼的候选业务场景

## 结论

可以从源码主动发现候选场景，不必先由用户逐条回忆。源码能够证明某个业务流程、状态机、配置项或失败处理在 FOBrain 中存在；**不能证明目标部署正在使用、哪个岗位承担、频率／成本／后果，或新产品值得建设。**

因此本清单用于主动缩小访谈范围：先从源码筛出高摩擦或高风险流程，再只向业务方验证少数关键事实。

除明确标有 TS-002 的条目外，每条 canonical 状态均为：`PROJECT_HISTORY / DIRECT / UNKNOWN / SOURCE_ONLY / OPEN / NOT_NORMATIVE`。

## 不应作为新产品的重复范围

- 仅把原生“自动派发、转交、延时、催促、误报、复测”按钮换到新界面；源码已证明这些属于原生闭环。
- 只展示全局资产或漏洞统计；除非能证明统计后的决策／异常处置仍存在明显摩擦。
- 没有目标任务证据就把 24 个工具全部做成聊天入口。

## 建议的发现顺序

1. **SC-02 修复延迟处置**：已有用户信号称其最频繁，先还原一次真实实例。
2. **SC-03／SC-06 新增漏洞派发与结果对账**：已有 100+ 条／半天工作量，补齐错派、漏派、授权和实际写入证据。
3. **SC-01 自动派发配置预检／例外队列**：只在验证原生规则确有未覆盖／失败／批量风险后继续。
4. **SC-04 数据源新鲜度影响排查**：优先于低价值的资产在线报表。
5. **SC-05 合规闭环**：作为独立领域采样，不能默认与漏洞工作流合并。
