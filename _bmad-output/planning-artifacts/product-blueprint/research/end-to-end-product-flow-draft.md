# 端到端产品主流程草案

## 用途与边界

本文件先把已收集的真实场景连接成一条产品主流程，作为后续用户故事的共同骨架。它不是最终 PRD、技术架构或已批准首版范围：每个环节只采用已记录的用户／源码／当前项目证据，缺口明确保留，不由 AI 补写。

当前工作假设：这是接入部分 FOBrain 既有接口、验证工作流的实验性 Agent，帮助产品中心／运营发现并处理漏洞处置中的人工例外；不构建完整漏洞运营平台。AI 只能协助读取、整理、提示和准备动作，不能自行写入外部系统。

## 主流程

```text
发现工作项
  → 查询并汇总业务事实
  → 人工判断与沟通
  → 选择一个明确动作
  → 管理员二次确认
  → 受控写入
  → 回读核验
 → 成功反馈或缺陷上报
```

## 共用漏洞卡片（已确认）

派发、延时、误报、转发等所有漏洞操作共用同一套漏洞卡片／列表基础内容：**POC、IP、IP 在线／离线状态、业务系统、修复负责人**。各动作只在此基础上增加本次修改、确认或结果字段；不能因操作类型而丢失这些基础事实。

| 步骤 | 产品要完成的事 | 已确认场景与证据 | 当前缺口／限制 |
| --- | --- | --- | --- |
| 1. 发现工作项 | 展示需要人工关注的业务工作项，或明确没有工作项。 | TS-002：每日查看所有新增漏洞；无结果时固定显示“没有待派发漏洞”，由接口事实决定；TS-005：每周发生直接延时；TS-001：半年一次业务主机盘点。 | 当前项目无法精确查询仅“新增”状态；TS-005 的待延时列表来源尚未确认。 |
| 2. 查询并汇总业务事实 | 为工作项展示可核验的统一漏洞卡片和动作上下文。 | 所有漏洞操作卡片均显示 POC、IP、IP 在线／离线状态、业务系统、修复负责人；TS-002 选人还需查看业务负责人、运维负责人；TS-005 还需展示新期限和原因。 | 当前 Product Facts 仅保留摘要，不能提供逐行业务事实；资产状态筛选和业务到 IP 关系尚未验证。 |
| 3. 人工判断与沟通 | 运营与相关人员决定是否要处置以及目标结果。 | TS-002：运营结合漏洞、IP、在线状态、业务系统、业务负责人、运维负责人指定人员；TS-005：是否延时和新期限均由人工沟通后决定。 | TS-002 的可选人员范围和实际批量方式未收集。 |
| 4. 选择明确动作 | 将每个决定落到单一业务动作，不混合多个例外。 | TS-002：先逐条判断负责人，同一负责人可合并多条派发，不同负责人逐条派发；TS-005：对一条漏洞直接延时；误报、转发另行拆分。 | FOBrain 源码支持多接收人，但实际流程不允许不同负责人混合派发。误报与转发的源码状态约束不同，尚未形成真实任务。目标部署写入接口未验证。 |
| 5. 管理员二次确认 | 所有数据修改在写入前由管理员确认目标与变化。 | Owner 确认全产品默认规则；TS-005 已确认确认信息；TS-002 合并派发时必须逐条展示每条 POC、IP、在线状态和指定负责人，不能只显示数量。 | 取消行为、审计需求及其他动作确认字段仍须逐项定义。 |
| 6. 受控写入 | 仅在权限和确认均满足后提交外部修改。 | TS-005：仅管理员可直接延时；当前 FOBrain 原系统没有本产品的确认机制。 | 当前 Eino 没有任何 live 验证的漏洞写域 capability；DG-08／DG-09 未通过，禁止实施。 |
| 7. 回读核验 | 不能只相信接口成功，核验业务结果已真正变化。 | TS-002：接口成功且负责人变为指定人；TS-005：状态为延时且期限为指定值。FOBrain 派发源码还可能先过滤离线资产，过滤后为空仍返回成功。 | 缺少目标部署写入／回读接口及 Product Facts 逐字段承载能力。 |
| 8. 反馈或缺陷上报 | 核验成功才完成；否则不得伪报成功。 | TS-005：成功仅提示“延时成功”；失败或不一致联系 FOBrain 系统负责人，漏洞仍未完成。TS-002：结果逐条展示 POC、IP、IP 在线／离线状态、业务系统、修复负责人和结果；合并派发逐条结算，失败项待排查；FOBrain 自动通知，产品不重复通知；失败时联系 FOBrain 系统负责人排查。 | 故障归属已统一为 FOBrain 系统负责人；重试、工单化和告警规则未确认。 |

| 场景 | 位置 | 当前结论 |

| TS-001 公司业务主机在线盘点 | 步骤 1～2 的只读验证样本 | 已证实低频且低直接成本；不作为 MVP 驱动。 |

| TS-005 单条漏洞直接延时 | 步骤 3～8 的已细化候选 | 每周、每次约几分钟；已明确人工决策、管理员确认、回读与失败闭环；仍缺工作项发现方式、写域接口和各项部署治理证据。 |
| TS-003 自动派发配置 | 后续能力候选 | Owner 已确认“按业务系统自动派发”是本产品未来新增能力，不是本轮主流程或首版必做项；FOBrain 全局配置接口仅作未来支撑线索。 |
| TS-004 误报标记／责任人转发 | 后续单独场景 | 已确认必须拆分，尚未收集各自真实任务。 |

## 全局写入不变量（已确认）

1. AI 不自动决定或执行数据修改。
2. 所有数据修改必须由有权管理员进行二次确认后才可写入。
3. 确认必须先让管理员核对目标对象和将发生的变化；具体字段按动作定义。
4. 接口成功不等于任务成功；必须按动作回读业务结果。
5. 回读失败或不一致不得显示成功，必须进入明确的故障处理路径。
6. 本产品不做任何通知功能；FOBrain 自身自动通知不属于本产品能力、成功条件或验收范围。

## 进入正式 PRD 前的最小门槛

1. 选择一个场景作为首轮验证对象，不能同时把所有候选写为首版范围。
2. 为该场景补齐发现来源、角色权限、确认字段、外部写入与回读证据、失败补救和数据治理。
3. 通过 DG-04～DG-09，才能将草案升级为正式 Product Issue／PRD 要求。
