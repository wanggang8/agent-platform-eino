# 本轮实验 Agent 目标包

## 结论

建议本轮实验不恢复 24 个只读工具，也不做完整漏洞运营平台。以已确认的人工漏洞处置流程为主线，选择 **7 个代表性只读能力 + 4 个受控写动作**。它覆盖身份权限、资产、漏洞、业务系统和“读取—人工判断—确认—写入—回读”完整闭环。

本文件是范围提案，不是技术实施计划。所有写动作仍须在写域证据、二次确认、回读和失败补救门禁通过后才可实施。

## 建议纳入的只读能力

| 代表维度 | 建议能力 | 当前 live 证据 | 为什么纳入 |
| --- | --- | --- | --- |
| 身份 | `tool.fobrain.current_user_context` | passed | 实验必须知道当前操作者是谁，支撑“接口内置权限范围”解释。 |
| 权限 | `tool.fobrain.my_permissions` | passed | 展示／核对 FOBrain 内置可见范围，产品不得越权。 |
| 资产列表 | `tool.fobrain.list_assets_by_ip` | passed | 用 IP 查询资产与在线状态，是统一漏洞卡片的关键上下文。 |
| 资产详情 | `tool.fobrain.get_asset_detail` | passed | 代表从资产列表进入单资产事实核对。 |
| 漏洞列表 | `tool.fobrain.list_vulnerabilities_by_ip` | passed | 用 IP 关联漏洞，支撑资产—漏洞联查。 |
| 漏洞详情 | `tool.fobrain.get_vulnerability_detail` | passed | 代表从漏洞列表进入单漏洞处置前核对。 |
| 业务系统 | `tool.fobrain.business_list` | passed | 为卡片的业务系统上下文提供代表性业务读取。 |

## 建议纳入的写动作

| 写动作 | 已确认业务闭环 | 当前项目状态 |
| --- | --- | --- |
| 手动派发 | 全部新增漏洞→按发现时间倒序→人工看统一卡片及业务负责人／运维负责人→从全员列表选人→同一负责人可合并→二次确认→负责人回读→逐条结果。 | 当前无精确“新增”查询、人员列表、写入或回读 capability。 |
| 直接修复延时 | 人工沟通决定→管理员对单条漏洞确认→写入→状态“延时”及期限回读→成功提示／失败上报。 | 当前无写入／回读 capability。 |
| 误报标记 | 操作人对自己负责漏洞人工判断→二次确认→状态“误报”回读→失败上报。 | 当前无写入／回读 capability。 |
| 错派转发 | 用户主动选择可见漏洞并从全员列表选接收人；同一接收人可合并，二次确认后逐条回读负责人变更，失败逐条待排查。 | 当前无人员列表、写入／回读 capability；进入实现前必须补齐。 |

## 主流程必需但当前缺失的能力

这些不是“额外功能”，而是已确认主流程无法成立的事实缺口：

1. 精确读取当前用户可见的**全部新增漏洞**，按发现时间倒序；空结果稳定显示“没有待派发漏洞”。
2. 提供 FOBrain 全部人员列表，供运营人工选择负责人。
3. 向统一漏洞卡片安全提供：POC、IP、IP 在线／离线、业务系统、修复负责人；派发判断还需业务系统负责人和运维负责人。
4. 对上述四项已细化写动作提供：动作级权限、二次确认、写入、逐条回读、部分失败和缺陷上报。

## 明确不纳入本轮

| 范围 | 原因 |
| --- | --- |
| 其余 17 个已通过只读工具 | 能调用不等于支撑当前实验主流程；避免恢复清单驱动的范围膨胀。 |
| 6 个“我的／本部门范围”工具 | 当前 live blocked，不能作为实验依赖。 |
| `pending_tickets` | 当前 live skipped，不能作为实验依赖。 |
| 自动派发配置 | Owner 已确定为后续新增能力。 |
| 通知、邮件、webhook、催办、通知中心 | Owner 明确不做；FOBrain 自身通知不属于本产品能力。 |
| 指标统计、外部高危、威胁关联、业务风险摘要 | 可在后续真实任务证明价值后再纳入；当前不支撑手动处置闭环。 |

## 实验成功判定（范围级）

1. 用户能基于 FOBrain 的真实、授权范围内事实查看统一漏洞卡片，而非 raw payload 或模型猜测。
2. 手动派发、直接延时、误报标记均只有在二次确认后才允许写入，且必须回读业务结果。
3. 任何失败、部分失败或回读不一致均不得伪报成功。
4. 产品不新增任何通知功能。

## Owner 确认

Owner 于 2026-07-13 确认本目标包。它成为本轮实验的范围基线：后续 Product Brief／PRFAQ／PRD 只围绕这 7 个代表性只读能力和 4 个写动作展开。四项写动作的业务流程已确认，但目标部署写入与回读能力均仍是实现准入条件。
