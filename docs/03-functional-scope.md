# 功能范围

本文定义产品能力范围。它不描述具体技术实现、实施阶段或验收命令。

## 范围原则

本次完整重构目标是 P0 + P1 + P2。

P0/P1 是交付顺序，不是最终终点。只有 P0、P1、P2 全部完成，才算重构完成。

## P0：最小产品闭环

P0 必须完成：

- 新 Workbench 产品入口。
- 普通聊天。
- assistant 流式输出。
- 本地测试工具调用。
- 工具卡展示。
- 工具结果安全结构化。
- Action API 最小返回。
- 前端视觉不跑偏。

## P1：产品级运行能力

P1 必须完成：

- 业务能力插件化接入边界。
- Fobrain 3 个只读工具 PoC。
- 审批 waiting / resume。
- 澄清 waiting / resume。
- 审计。
- 回放。
- Inspector evidence / structured / audit。
- 真实模型能选择并调用 PoC 工具。

## P2：产品能力恢复与对比

P2 必须完成：

- Fobrain 24 个只读工具矩阵。
- connector 状态。
- 凭据绑定展示。
- 实体消歧澄清。
- 写域工单审批。
- 真实环境只读能力。
- 真实环境写域能力。

P2 是完整重构的必做范围，不是增强项。未恢复这些能力前，不声明重构完成，不声明产品能力可比，不替换当前产品基线。

## 明确延后

- 多租户。
- 计费。
- 完整 RBAC。
- worker 集群。
- 高可用部署。
- 全量生产迁移。

## 不允许丢失的产品边界

- Workbench 和 Action API 共用事实。
- 工具结果只从安全结构化结果展示。
- 审批和澄清必须进入审计与回放。
- secret 和 raw provider payload 不进入产品输出。
- 前端视觉必须保持当前工作台体验，不变成营销页、玩具页或原始事件展示器。
