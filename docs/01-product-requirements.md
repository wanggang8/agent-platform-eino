# 产品需求

本文只描述产品要什么，不描述框架、数据库、恢复机制、契约生成器等实现细节。

## 用户与入口

### Workbench 用户

用户通过 Web Workbench 输入自然语言，查看消息、工具卡、审批卡、澄清卡、运行状态、审计和回放。

### 外部系统

外部系统可以提交任务，并获得安全结构化任务结果。外部入口与 Workbench 必须能关联同一次运行，不允许出现两套互相独立的执行结果。

## 核心流程

### 普通聊天

- 用户输入消息。
- 系统流式返回 assistant 文本。
- 最终回答显示在主聊天。
- 失败时显示安全错误摘要和可重试提示。

### 工具调用

- 系统可以选择工具完成任务。
- 工具执行过程在时间线中显示。
- 工具结果以卡片展示。
- 工具卡展开后展示安全结构化结果。
- 用户不应看到 raw provider JSON、凭据、token、raw prompt、内部 reason code。

### 审批

- 高风险操作必须先显示审批卡。
- 未审批前不得执行真实 mutation。
- 用户可以 approve 或 reject。
- 重复审批必须幂等。
- 审批结果必须进入审计和回放。

### 澄清

- 当实体、目标或参数不明确时，系统显示澄清卡。
- 用户提交澄清后，系统继续执行。
- 重复提交、取消、超时必须有稳定状态。

### 审计与回放

- 用户可以查看一次运行的安全事件。
- 用户可以回放消息、工具、审批、澄清和最终结果。
- 审计和回放不能泄露 raw prompt、secret、Authorization、raw credential、raw provider payload。

### Action API

- 外部客户端可以提交任务。
- 返回结果必须包含运行状态、最终回答、从安全结构化工具结果派生的展示摘要、审批/恢复引用或错误摘要。
- 等待审批或澄清时，返回不可复用的安全引用。
- 外部 API 与 Workbench 展示必须能指向同一次运行。

## Fobrain 产品能力

P1 只要求 3 个只读工具 PoC：

- 当前用户上下文。
- 我的资产。
- IP 统计。

P2 必须恢复以下能力；未完成不得声明完整重构完成或产品能力可比：

- 24 个只读工具。
- connector 状态。
- 凭据绑定展示。
- 实体消歧澄清。
- 写域工单状态更新审批。
- 真环境只读验收。
- 真环境写域验收。

未通过恢复门禁前，只能声明 “Fobrain provider PoC 可用”，不能声明 “Fobrain 产品能力可比”。

## 非目标

- 不直接替换当前主项目运行路径。
- 不服务旧静态 Workbench。
- 不实现旧接口兼容层。
- 不把 Fobrain 或任一业务系统写进 runtime 核心。
- 不在 P0/P1 一次性复制全部生产能力；P2 仍必须按恢复门禁恢复既有关键产品能力。
- 不做 SaaS 多租户、计费、完整 RBAC、worker 集群。

## 产品成功表现

- 普通聊天、工具调用、审批恢复、审计回放、Action API 都能跑通。
- Workbench 与 Action API 使用同一套安全事实。
- 工具卡只展示结构化安全结果。
- assistant 主聊天不出现内部技术串。
- Workbench 视觉与当前产品体验可比。
